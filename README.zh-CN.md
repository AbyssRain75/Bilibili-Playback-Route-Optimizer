# Bilibili Playback Route Optimizer

[English](README.md) | 简体中文

观察和优化 B 站（bilibili.com）点播、直播 CDN 线路的浏览器扩展，适用于 Chrome 和 Edge。

默认是**观察模式**，只记录、不改动：播放器分到了哪些节点、实际从哪些节点取数据、各节点的首字节时间和速率、哪里卡了。打开**线路优化**后，扩展会在播放器拿到播放地址之前改写它，换到更快的节点，避开近期卡过的节点和 PCDN；打开**自动测速**后，会在缓冲充足时测各节点的速度，作为选节点的依据。两个开关默认都是关的。

> 本项目与哔哩哔哩没有关系，不是官方工具。

## 功能

- **观察与记录**：记下每次播放的节点分配，实际媒体请求的节点、IP、首字节时间、速率和失败，以及起播时间和卡顿。在 popup 里看当前页面，在统计页里看汇总。
- **线路优化**（默认关）：
  - 点播：可以指定一个节点，也可以选「自动」。「自动」会避开近 30 分钟卡过的节点；主节点是 PCDN 时换到官方节点；有测速结果时，得分比当前主节点高 20% 以上才换，避免来回切换。原来的地址都留作备用，换过去的节点不可用时，播放器会自己退回。
  - 直播：在 B 站给的线路之间选 FLV 或 HLS，同一条线路里 PCDN 排到官方节点后面、卡过的排到最后。「自动」在一种格式在当前清晰度上频繁卡顿时改用另一种，HLS 测速跟不上码率时改用 FLV。
- **自动测速**（默认关）：有 B 站页面在播放时每 30 秒测一轮，只在缓冲充足时测（点播前方缓冲 15 秒以上或暂停着，直播 1 秒以上），不和播放抢带宽。每个节点最多下载 512 KB，一轮最多约 2 MB；测得差的节点会少测。测速结果按网络分开保存，回到同一个网络时直接参考以往的结果。
- **卡顿识别与手动标记**：自动识别缓冲卡顿、起播慢和没能起播，按各节点当时的请求情况分摊责任。觉得卡的时候，可以用播放器控制栏上的小旗子、popup 里的按钮或快捷键 Alt+Shift+K 标记；标记时会记下前方缓冲和掉帧，分得清是网络问题还是解码跟不上。
- **统计页**：节点表（请求数、失败率、首字节、速率、测速、卡顿）、手动标记记录、会话时间轴和网络变化，可以按本日、本周、安装以来筛选，可以导出 JSON。
- **中英文界面**：按浏览器的界面语言自动选，popup 和统计页右上角可以手动切换。

PCDN（MCDN）是 B 站租用的家庭宽带、P2P 等节点，稳定性和跨网速度普遍不如官方 CDN，在海外更明显。

## 安装

需要 Chrome 或 Edge 120 及以上版本。扩展暂时没有上架商店，请用「加载已解压的扩展」安装：

1. 在 [Releases](https://github.com/AbyssRain75/Bilibili-Playback-Route-Optimizer/releases) 页下载最新版的 `Bilibili-Playback-Route-Optimizer-<版本>-chromium.zip`，解压到一个固定的文件夹。
2. 打开 `chrome://extensions`（Edge 是 `edge://extensions`），打开「开发者模式」（Edge 叫「开发人员模式」，在左侧栏底部）。
3. 点「加载已解压的扩展程序」（Edge 是「加载解压缩的扩展」），选择解压出来的文件夹（里面直接就是 `manifest.json`）。
4. 刷新已经打开的 B 站页面：扩展只对安装以后加载的页面生效。

也可以 `git clone` 本仓库，加载其中的 `chromium` 文件夹，内容和 zip 相同。

Edge 会把扩展图标收进工具栏的拼图菜单，可以点「在工具栏中显示」。

Firefox 版还在适配，暂时不能用。

### 更新

下载新版的 zip，先清空原来的文件夹，再把新版解压进去，文件夹的位置不变（用 git 的话在仓库里 `git pull`）。然后在扩展管理页点扩展卡片上的重新加载按钮，再刷新 B 站页面。记录和设置都会保留。

- **不要点「移除」**：移除扩展会删掉它保存的全部数据。
- **不要移动文件夹**：已解压的扩展按文件夹路径区分，换了位置就是另一个扩展，数据是空的。
- 保险起见，更新前可以先在统计页导出一份 JSON。

## 使用

点工具栏上的扩展图标打开 popup：

- 右上角的**启用**是总开关。关掉后整个扩展暂停（不记录、不改写、不测速），B 站照常播放。
- 在**线路设置**里打开**线路优化**和**自动测速**，选点播节点和直播线路。改动对之后加载的视频和直播间生效，正在看的要刷新页面。
- **手动问题标注**：少量卡顿、较多卡顿、无法播放、音画不同步，可以附备注，也可以撤销。
- **高级**里是近期问题、测速结果和节点明细。
- 右上角的**统计**打开统计页。

播放器控制栏右侧有一面小旗子：点一下记为「较多卡顿」；鼠标移上去会显示当前的播放状态（前方缓冲、掉帧、码率、正在用的节点和它的下载速度）和标记菜单。不需要的话可以在 popup 里关掉。

快捷键 Alt+Shift+K 直接记为「较多卡顿」，可以在 `chrome://extensions/shortcuts`（Edge 是 `edge://extensions/shortcuts`）里修改。

需要知道的几点：

- 改写只在播放器拿到播放地址时发生，正在看的视频要刷新页面（或者切到下一个视频）才会换节点。
- 直播只能在 B 站给的几条线路之间选，换到别的节点会被拒绝。
- 测速取的是文件中间随机的一段，边缘缓存节点（如 Akamai）没有缓存时要回源，测出的得分可能比实际播放时低。

## 隐私

- 记录只保存在本机浏览器的扩展存储里，不上传到任何地方，也没有统计或分析服务。
- 扩展自己只发两种请求：向 B 站的接口（`api.bilibili.com/x/web-interface/zone`，不带 cookie）查当前网络的国家、地区、城市和 ISP，用来区分不同网络下的测速结果，记录里不存 IP；以及打开自动测速或线路优化后，对 B 站 CDN 节点的测速请求。
- 只记有播放的页面，个人空间、动态这类没有播放的页面不记。
- 记录默认保留 15 天，可以在统计页右上角的「记录保留」里改成 7 天到 6 个月，超过的自动删除。
- 导出 JSON 默认是**普通导出**（脱敏）：没出问题的会话，页面地址和视频编号换成编号，网络位置只保留国家和 ISP。反馈问题时用这个。**完整信息导出**包含看过的所有页面、网络位置历史和节点 IP，请不要公开分享。

## 权限说明

| 权限 | 用途 |
|---|---|
| `storage`、`unlimitedStorage` | 在本机保存设置、记录和测速结果。记录多了会超过扩展存储默认的容量上限 |
| `webRequest` | 观察 B 站媒体请求的节点、IP、首字节时间、速率和失败。只读，不拦截、不修改 |
| `alarms` | 自动测速每 30 秒一轮的定时器 |
| `declarativeNetRequestWithHostAccess` | 只给扩展自己发出的测速请求加上 B 站的 Referer（CDN 要求有），不影响页面的请求 |
| `*.bilibili.com` | 在 B 站页面上运行脚本：读取和改写播放地址、记录起播和卡顿、显示播放器上的标记按钮；查询网络位置 |
| `*.bilivideo.com`、`*.bilivideo.cn`、`*.akamaized.net`、`*.szbdyd.com` | B 站的 CDN 和 PCDN 域名：观察媒体请求、测速 |

## 参考

下面这些项目给了思路，本项目没有使用它们的代码：

- [stabruriss/bilibili-accelerator](https://github.com/stabruriss/bilibili-accelerator)：缓冲充足时才测速、PCDN 的识别和排后、不伪造 Akamai 签名。
- [bilibili-cdn-switcher](https://github.com/a0972199950/bilibili-cdn-switcher)：原地址留作备用，出错先退回 B 站自己的备用节点。
- [Shaka Player](https://github.com/shaka-project/shaka-player) 的分组播放统计，[enhanced-h264ify](https://github.com/alextrv/enhanced-h264ify) 对硬件解码能力的说明。
