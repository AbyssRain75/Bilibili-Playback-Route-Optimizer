## 安装与更新

### 首次安装

1. 打开[最新发布页](https://github.com/AbyssRain75/Bilibili-Playback-Route-Optimizer/releases/latest)，在 **Assets** 中下载 `Bilibili-Playback-Route-Optimizer-<版本>-chromium.zip`。
2. 解压到一个准备长期保留的文件夹，确认里面直接包含 `manifest.json`。GitHub 自动生成的 **Source code** 归档是整个发布仓的源码；要按本步骤安装，请下载前面列出的扩展包。
3. 在浏览器地址栏打开 `chrome://extensions`（Edge 为 `edge://extensions`），打开「开发者模式」（Edge 为「开发人员模式」）。
4. 点击「加载已解压的扩展程序」（Edge 为「加载解压缩的扩展」），选择直接包含 `manifest.json` 的文件夹。
5. 在工具栏的扩展菜单里固定图标，或在 Edge 中选择「在工具栏中显示」。
6. **刷新已经打开的 B 站页面**，播放一个视频或进入直播间，再点击扩展图标。

习惯用 Git 的用户也可以克隆本发布仓，直接加载 `chromium/` 文件夹，无需安装 Node.js 或运行构建。

### 更新并保留数据

1. 如需留存诊断数据，先在统计页导出 JSON。
2. 下载并解压新版扩展包，确认文件完整。
3. 用新版文件整体替换**原来加载的扩展文件夹内的内容**，保持加载路径不变；通过 Git 安装的，在发布仓中执行 `git pull`。
4. 在扩展管理页点击扩展卡片上的「重新加载」，再刷新已打开的 B 站页面。

设置与记录保存在浏览器的扩展存储中。**不要移除扩展，也不要移动加载文件夹**：移除扩展会删除数据；换路径加载可能产生新的扩展 ID，原数据就无法在新 ID 下读取。JSON 导出用于分析，当前没有导入记录的功能。

## 快速开始

安装后默认是**观察模式**。先正常观看，扩展会记录实际媒体节点、起播、卡顿和请求表现。

想尝试自动选线时：

1. 切到正在播放的 B 站标签页，打开扩展面板。
2. 保持右上角「启用」打开，在「线路设置」里打开「线路优化」。
3. 将「点播节点」和「直播线路」保持为「自动」。需要持续积累测速结果时，再打开「自动测速」。
4. 刷新 B 站页面。选线在重新获取播放地址时进行，设置不会立即替换正在下载的媒体连接。
5. 遇到问题就标记；面板提示「刷新换节点」时，可以在方便中断播放时刷新。

线路优化与自动测速可以独立开关：只开测速时不改播放线路；只开优化时也能使用近期问题与已有测速，且可能触发复测。

## 面板与设置

面板优先显示当前标签页。查看另一段播放时，先切到它所在的标签页再打开面板。

| 设置 | 默认值 | 用途与生效时机 |
|---|---|---|
| 启用 | 开 | 总开关。关闭后暂停记录、地址改写、测速与标记；已有设置和记录保留，B 站页面主题照常。已经在播的不会自己切回原线路，暂停后刷新页面才按 B 站原来的设置播；重新启用后也要刷新 |
| 线路优化 | 关 | 开启播放地址改写。改动在下次取得播放地址时生效，当前页面通常需要刷新 |
| 自动测速 | 关 | 启用周期测速，缓冲条件满足后运行 |
| 点播节点 | 自动 | 按近期问题和测速选节点，也可从列表指定节点；需开启线路优化 |
| 直播线路 | 自动 | 自动判断，或选择「FLV优先」「HLS优先」；需开启线路优化 |
| 播放器标记按钮 | 开 | 显示播放器控制栏右侧的小旗子 |
| 界面语言 | 跟随浏览器 | 中文浏览器界面显示中文，其他显示英文；面板和统计页右上角可手动切换 |
| B 站页面主题 | 不改 | 把 B 站网页换成浅色、深色或跟随系统，已打开的页面马上换；不受「启用」影响 |
| 关闭 B 站 P2P（测试功能） | 关 | 让 B 站网页播放器不用 P2P、点播和直播都改走 HTTP，主要影响中国大陆网络；刷新页面后生效，暂停时不起作用；见下面的「关闭 B 站 P2P（测试功能）」 |
| 记录保留 | 15 天 | 在统计页设置，可选 7、15、30 天或 2～6 个月，每个月按 30 天计算 |

语言按钮显示切换目标：「EN」切到英文，「中文」切到中文。切回浏览器本来的语言就恢复跟随浏览器。面板、统计页与播放器按钮会同步切换；浏览器扩展管理页里的简介仍由浏览器语言决定。

「B 站页面主题」用的是 B 站自己的深色主题（登录后头像菜单 → 主题里的那个），没登录也能用；B 站没做深色的页面不会变。选了浅色、深色或跟随系统后，扩展会把 B 站记主题的 cookie（`theme_style`）改成一样的，在头像菜单里换了主题，面板里的选择也跟着变；在面板里换了，已打开页面的头像菜单也跟着变。「跟随系统」按系统的浅色 / 深色，系统换了已打开的页面跟着换。选回「不改」后按 B 站自己的设置显示：没登录是浅色，登录了按最后一次选的主题。为了少闪一下浅色，扩展在每个 B 站子域名的 localStorage 里记一个提示（`bilicdn:theme`，记着选的是哪种），页面一打开就先按它换；选回「不改」后，开着的页面马上删掉它，其他子域名的等下次打开页面时删。头一次打开某个子域名（如 `search.bilibili.com`）的页面时还没有这个提示，可能先闪一下浅色。

### 关闭 B 站 P2P（测试功能）

在中国大陆，B 站网页播放器常把大部分音视频数据走 B 站自己的 P2P（浏览器之间的 WebRTC 连接，实测点播一个热门视频八成以上、直播六到九成）：在你的浏览器和其他观众之间传数据，直播几分钟就可能上传几十 MB；点播会把看过的视频存在浏览器里给别人取；这部分扩展也看不到（见下面的「扩展看不到的流量」）。B 站网页上没有关掉它的选项。

1. 在面板里打开「关闭 B 站 P2P（测试功能）」（默认关着，不改 B 站的行为）。
2. **刷新 B 站页面**。播放器只在加载时读这个设置，已经打开的页面不刷新不变。
3. 之后点播和直播都改走 HTTP。播一会儿再到统计页看：「媒体请求」下面那一行的悬停说明和节点分布的结论里会写有几个会话关了 P2P。统计总览会把所选时间范围里以前用过 P2P 的记录也算进去，所以 P2P 占比不一定马上降到 0。

几点说明：

- 这是测试功能，**扩展里的这个开关还没在中国大陆网络上实测过**。做法依据的是此前在大陆网络上手动关掉 P2P 的实测：点播 P2P 变成 0、直播不再建 P2P 连接、上传从几十 MB 降到约 1 MB，播放正常，首帧没有变慢；但那次只测了两个低码率视频、两个直播间，用的是数据中心网络，家庭宽带上效果怎样还不知道。
- 主要影响中国大陆网络；播放器本来就不用 P2P 的话（海外网络大多如此），开不开差别不大。
- 在 P2P 效果好的网络上，关掉后可能更慢。觉得变慢了，关掉开关、刷新页面就恢复。
- 依赖 B 站播放器的内部配置，B 站改了就会失效，失效时等于不改，播放不受影响。
- 关掉 P2P 后，大陆的点播可能有一大半走不在扩展网站权限里的 PCDN，扩展照样看不到（统计页算「扩展看不到的 HTTP」）；同时开线路优化「自动」时，会尽量换到 B 站的官方镜像，但不一定总有能换的。
- 暂停扩展（关闭「启用」）时不起作用。关掉这个开关或暂停扩展后，要刷新页面才会恢复用 P2P。之前已经存在浏览器里的 P2P 缓存不会被清理。
- 扩展只改播放器在页面里读到的开关（点播的播放器配置、直播的播放地址分配），不改 B 站存着的配置，不删浏览器的 WebRTC 功能，也不需要新的权限；另在 B 站页面的 localStorage 里记一个提示（`bilicdn:p2p`），让设置晚到时也能生效，关掉开关后删掉。

「当前播放」和「高级」里的信息可以结合来看：

| 指标 | 含义 |
|---|---|
| 前方缓冲 | 已经下载、尚未播放的时长。缓冲很少且反复转圈时，网络或节点可能跟不上 |
| 近期掉帧 | 近一段时间解码或渲染丢失的画面帧。缓冲充足但掉帧明显时，可尝试降低画质或检查硬件解码 |
| 会话卡顿 | 当前播放会话自动识别的缓冲问题，拖动进度引起的等待单独区分 |
| 正在用的节点 / 节点明细 | 实际请求的 CDN，不等于播放接口给出的所有候选节点；音频与视频可能来自不同节点 |
| 近期问题 | 节点与直播协议的近期证据，以及自动选线会不会避开它们 |
| 测速结果 | 扩展主动测试得出的结果、暂缓原因和地址是否已过期 |

页面请求的「下载速度」与测速「得分」口径不同。下载速度主要看数据传输阶段，测速得分还会考虑首字节等待和分片下载方式；直播长连接或过小的分片可能没有可显示的页面下载速度。

## 线路优化

### 点播：自动或指定节点

自动模式会避开近期判定为卡过的节点和 PCDN。原主节点近期没有问题时，候选节点的测速得分需高出约 20% 才会换；没有测速或问题证据时，继续使用 B 站分配的官方节点属于正常情况。

自动模式还会看页面实际请求的表现（近 **30 分钟**里每个节点的首字节和成败）：B 站分配的节点在页面上表现好（至少 5 个请求、首字节中位数不超过 **60 ms**、失败不到 10%），测速得分再高也不换；页面上用过、比原节点差的节点（失败多，或首字节慢 20% 以上）不会按测速换过去。按测速换过去的节点近 30 分钟要测过 **3 次**，「探查」每个节点只测一次，不算在内；页面上已经用过、表现好的节点不用等测满次数，但测速得分同样要高出约 20%。原主节点卡过或是 PCDN、必须换时，先换到页面上表现好的节点，其次是测过几次的测速最好的节点，再按 B 站分配的顺序。

近期节点问题按最近 **30 分钟**统计，并按责任和严重程度累计。一次「少量卡顿」不一定马上触发换线。连到同一服务器的几个镜像名会共同承担问题证据，避免只换域名却仍访问同一台服务器。

手动指定点播节点后，刷新页面再对比效果；不合适时改回「自动」并刷新。不同节点的可用性取决于视频地址和当前网络，原地址会保留为备用，播放器能否顺利回退仍取决于播放器本身。

备用地址也会调整顺序：官方节点在 PCDN 前，近期出过问题的节点排到后面。「主地址不变，调整备用顺序」表示扩展只排序了备用地址，主节点没有换。

### 直播：自动、FLV优先、HLS优先

直播只在 B 站为当前直播间提供的线路与格式中选择，不能任意替换 host。网页端支持的选择包括 FLV 与 HLS fmp4；只有 HLS ts 或缺少目标格式时，扩展不会强行改成不存在的线路。

- **自动**：结合近期节点问题、当前清晰度的协议问题、测速和本网络历史判断；HLS 跟不上码率时可能改用 FLV。
- **FLV优先**：尝试使用可用的 FLV 线路。
- **HLS优先**：尝试使用可用的 HLS fmp4 线路。

直播协议的问题证据按协议与清晰度保留 **12 小时**。HLS 下载占用长期很高，表示取分片几乎耗尽了播放时间，可能没有足够余量；即使某次测速峰值高，也可能反复缓冲。修改直播线路后刷新直播间，再观察缓冲和卡顿。

### 网络档案与限制

测速历史按 B 站识别的国家、地区与 ISP 区分；只变城市不会当成换网络。网络变化会重置近期排名与问题证据。回到用过的网络时，历史用于挑选复测对象，点播候选节点需复测后才按历史参与换线；结果通常用于下一次取得播放地址的播放。

PCDN 可能通过域名、端口、IP 地址或请求参数被识别。扩展会降低其优先级，保留原地址作为最后的回退选项。实际请求统计只覆盖已获网站权限的域名，不能保证统计到所有其他 PCDN 域名。

扩展不会解锁大会员、付费、地区或账号权限限制，也不改变视频本身的清晰度和编码选择。解码、渲染或音画同步问题不一定能通过换节点改善。

## 测速

周期测速每 **30 秒**尝试调度，有近期媒体请求才运行。每轮最多依次测试 4 个节点，每个最多读取约 **512 KB**，一轮合计约 **2 MB**，测 HLS 时还要另外取播放列表，会产生额外流量。节点会按排名、最近测试时间和失败退避轮换，不会每轮都测完列表。

能读到播放器状态时，每测一个节点前都检查：

- 点播：暂停，或前方缓冲至少 **15 秒**；快播完时，缓冲到结尾也行。
- 直播：没有在转圈，且缓冲至少 **1 秒**。

缓冲不足时暂缓，测试中缓冲降低时停止后续节点。线路优化触发的复测也遵守缓冲保护；读不到播放器状态时，周期测速可继续，复测会先等待，20 秒后仍读不到才继续。因此缓冲保护不是在所有页面状态下都能确认播放余量。

得分是估计的可持续速率，失败按 0 计；短时测试无法代表每个分片的真实表现。点播测速为了避开节点的缓存，取文件中间的一段（不保证一定没缓存），播放时取的多是已缓存的热门内容，两者的首字节可能差十倍，所以自动选线还参考页面实际请求的表现（见上面的「点播：自动或指定节点」）。近 **30 分钟**没有更新的测速不会继续用于自动选节点。本网络历史保留 7 天内每个节点最近 12 次得分，供复测与直播协议判断使用。

测速使用当前播放地址，地址接近签名有效期时会停止并提示；刷新页面取得新地址后才能继续。关闭「自动测速」会停止周期测试；要连优化触发的复测一起停止，关闭「线路优化」，或直接关闭总开关「启用」。

## 标记问题

| 入口 | 操作 |
|---|---|
| 播放器小旗子 | 点击直接标记「较多卡顿」；悬停可看状态，并选择「正常」「少量卡顿」「较多卡顿」「无法播放」「音画不同步」 |
| 扩展面板 | 在「手动问题标注」先填写可选备注，再点问题类型；备注最多 100 字符 |
| 快捷键 | 默认 **Alt+Shift+K**，标记「较多卡顿」 |

标错时点面板的「撤销」。播放器菜单在标记后 1 分钟内高亮最近的标记，选择「正常」可撤销它；超过 1 分钟恢复高亮「正常」，原标记仍保留。也可以使用刚标记后显示的撤销提示。

快捷键可以在 `chrome://extensions/shortcuts` 或 `edge://extensions/shortcuts` 修改。没有反应时检查是否已分配、是否与其他程序冲突，以及扩展是否启用。

扩展保存标记时的播放位置、缓冲、掉帧与相关节点，结合自动事件判断原因。音画不同步，以及被判断为掉帧或缓冲充足的标记，不会给节点累计卡顿权重。总开关关闭或当前标签页不是可标记的 B 站页面时，标记不可用。

## 统计与导出

### 阅读报告

点击面板右上角「统计」，选择「本日」「本周」或「安装以来」。日期范围按浏览器本地时间计算，只覆盖尚未过期删除的数据。

- **媒体请求**（顶部）：扩展记到的媒体请求数，下面一行是扩展看到了多少媒体流量、P2P 占多少、P2P 上传了多少，PCDN 加载器取过的也写上它取了多少，见下面的「扩展看不到的流量」。
- **节点分布**：按网络（B 站识别的国家、地区和 ISP）分开汇总，默认是当前网络，可以在右上角的选择框换别的网络。最上面是几条结论（B 站主要分配哪类节点、它在页面上表现怎样、有没有比它快得多的节点、PCDN 占多少、哪个节点卡得最多、哪些节点测不通、扩展看到了几成流量等），下面是各类节点的占比、同一台服务器的几个名字、这个网络的全部节点；去过两个以上网络时还有并排对比。见下面的「节点分布与探查」。
- **节点表现**：按域名搜索，筛选「全部节点」「有失败或卡顿」「有测速记录」「PCDN」，对比首字节、速度、失败、卡顿与标记。
- **问题标注**：查看问题类型、判断、备注与播放位置；点播的位置链接可用于重看当时的片段。
- **会话时间轴**：结合媒体请求、失败、起播、卡顿、标记与线路改写看问题发生顺序；需要时开启「全部会话」并点「显示更多」。
- **网络与页面**：查看页面类型分布与网络变化。

TTFB 是请求发出到响应头到达的时间；页面速率只计算足够大的响应。浏览器缓存直接答复的请求、主动中止与超时有各自的统计规则，详情可展开报告底部「统计口径」。统计页的「刷新」重新读取记录，不会刷新 B 站播放页面。

### 节点分布与探查

不同地方访问 B 站，分到的节点不一样，同一个节点在不同地方的快慢也不一样：有的地区 B 站分配的主节点就是最快的，有的地区备用节点比主节点快几十倍，中国大陆则常常分到 PCDN。所以扩展按网络分开记录和比较，一个网络的结论不会用到另一个网络上。

- **探查这个网络**：先在某个标签页里播放视频或直播，再在统计页点这个按钮。扩展会把这个视频或直播间的候选节点各测一次：点播是 B 站分配的节点、内置的 UPOS 镜像和几个只在探查时测的镜像，二十来个、约 10 MB；直播是 B 站给的各条线路。
- 自动测速关着也能用，但「启用」要开着。照样等缓冲：缓冲不够时先等，一共等了 2 分钟还不够就停下，测过的照样保留；暂停视频时照常测。同时开着好几个播放页时，测的是最近在下数据的那个。
- 测的结果和自动测速一样记下来，用来挑「自动」的候选；每个节点只测了一次，「自动」要等自动测速或复测再测几次才会按测速换过去（页面上已经用过、表现好的节点不用等）。只能探查当前所在的网络。
- 这个网络里测得好、又不在内置列表里的镜像，以后自动测速也会测，「自动」也会考虑。
- 结论里写「初步」的，测速次数还少（探查的一次不算），开着自动测速多看一会儿再来看。B 站分配的节点在页面上表现好时，结论只说它表现好，不会因为别的节点测速得分高就建议换。

### 扩展看不到的流量

扩展靠浏览器的 webRequest 看媒体请求，只看得到权限里那几个 B 站 CDN 域名上的 HTTP 请求。在中国大陆，B 站网页播放器常把大部分音视频数据走 B 站自己的 P2P（浏览器之间的 WebRTC 连接，实测点播一个热门视频八成以上、直播六到九成），不走 P2P 时又常走不在扩展网站权限里的 PCDN，这些扩展都看不到。统计、卡顿归因、节点分布和线路优化都只管得到扩展看到的那部分。

- 扩展读 B 站点播播放器自己按来源统计的字节数（HTTP、B 站的 P2P、PCDN 加载器），并统计页面里 WebRTC 数据通道收、发的字节数（直播只有这个），每 30 秒记一次，切到后台、离开页面时也记；B 站播放器自己每 5 分钟和关页面时会把这份统计清零，扩展会记下清零前的数，不会漏掉。只记字节数，不读内容，也不需要新的权限；不打开「关闭 B 站 P2P（测试功能）」时不改 B 站的 P2P。
- 打开了「关闭 B 站 P2P」的会话会单独记一笔，统计页写出有几个会话关了 P2P，免得把关掉的当成这个网络本来就不用 P2P。
- 「扩展看到的比例」= 扩展记到的媒体请求字节 ÷ 媒体数据：点播按播放器自己统计的字节，直播按请求字节加 P2P 收到的字节。媒体数据里除了扩展看到的和 P2P，剩下的是扩展看不到的 HTTP（比如不在网站权限里的 PCDN），占到 5% 以上时节点分布会写出来。B 站的 PCDN 加载器取的也是 HTTP，扩展看得到的已经算在「扩展看到」里，统计页只在它取过数据时另写一句它取了多少。统计页顶部「媒体请求」下面一行是所选范围的合计；节点分布里每个网络一条，扩展看到的不到一半时这一条排在最前面。P2P 上传量单独列出（直播的 P2P 会上传，可能和下载差不多多）。
- 旧版本的记录、读不到播放器统计又没用 P2P 的会话（比如海外的直播）没有这项，算「不知道」，不当成 0；统计页会写明按几个会话算。
- 读的是 B 站播放器的内部接口，B 站改了就读不到，这时只是没有这项，播放不受影响。

### 导出 JSON

1. 选择覆盖问题发生时间的统计范围。
2. 点击「导出 JSON」，默认选择「普通导出（脱敏）」。
3. 点「导出」保存文件；完整信息导出还需另一次确认。

| 类型 | 保留的信息 |
|---|---|
| 普通导出（脱敏） | 保留节点 host / IP、国家与 ISP；出过问题的会话仍保留视频或直播间地址与标记备注。其他会话的页面地址、视频编号、地区与城市会替换成编号，已撤销标记的备注去掉 |
| 完整信息导出 | 原样导出所选范围的记录，包括浏览页面、网络位置历史、节点 IP 和备注，只用于自行定位与分析问题 |

**普通导出仍可能包含个人信息，分享前检查内容；完整信息导出请自行保管。** 导出是文件保存，不会自动发送到项目或第三方。报告范围之外但用于理解范围内会话的必要上下文也可能随文件保留。

### 保留与清空

「记录保留」默认 15 天。缩短时长会导致删除时，统计页先显示数量与时间并请求确认；旧版本遗留记录首次删除也会先提示。自动清理按批次进行，过期数据可能多留几个小时；跨越保留边界的会话会保留必要的开头与分配信息。

「清空全部」需确认，会删除播放记录，并重置测速排名、近期问题和网络档案，设置保留。删除无法撤销，需要留存的先导出。保留时长变长不会恢复已经删除的记录。

## 桌面版（预览）

适用于桌面版 **0.1.0**。桌面版把扩展的观察、选线、测速和标记用在 Windows 版 B 站 PC 客户端里：它带调试端口启动客户端，在播放器窗口和直播窗口加载页面之前放进扩展的页面脚本，扩展的后台原样在桌面版里跑。所以上面各节写的面板、线路优化、测速、标记、统计与导出，在桌面版里用法相同，下面只写不一样的地方。现在是预览版，在客户端 1.19.0 上测过。

### 安装和启动

需要 Windows 10 / 11（64 位）和 B 站 PC 客户端。Node.js 已经放在 zip 里，不用另装。

1. 在 [Releases](https://github.com/AbyssRain75/Bilibili-Playback-Route-Optimizer/releases) 下载标着 **Pre-release** 的桌面版（标签以 `desktop-v` 开头）的 `Bilibili-Playback-Route-Optimizer-Desktop-<版本>-win-x64.zip`。
2. 解压到一个文件夹，里面应该有 `start.cmd`、`desktop`、`extension`、`node` 和 `LICENSE`。
3. 从托盘完全退出 B 站客户端（右键托盘图标 →「退出」；只关掉窗口的话客户端还在后台）。
4. 双击 `start.cmd`。桌面版启动客户端、接入后，在默认浏览器里打开面板。

从网上下载的文件，双击时 Windows 可能先弹出安全提示：`node.exe` 有 Node.js 官方的签名，`start.cmd` 是脚本，没法签名。可以在解压前右键 zip →「属性」→ 勾选「解除锁定」，再解压。

忘了退出客户端也没关系：控制台会提示，退出后桌面版接着启动它。客户端装在不常见的位置、桌面版找不到时，在文件夹的地址栏输入 `cmd` 回车，运行 `start.cmd --client "D:\…\哔哩哔哩.exe"`。

发布仓的 `desktop` 文件夹里是同样的文件（只少了 `node.exe`），装了 Node.js 22 以上的也可以直接双击那里的 `start.cmd`。

### 控制台窗口

| 操作 | 作用 |
|---|---|
| `p` | 打开面板 |
| `s` | 打开统计页 |
| `q`、Ctrl+C、关掉窗口 | 退出，客户端也正常退出 |

窗口标题显示当前状态（启动中、重连中、已暂停）。客户端被关掉时桌面版也跟着退出。客户端在上一次没正常退出后再启动时，有时会自己另起一个进程，连接会断：桌面版自动重连，已经打开的窗口补上脚本，断开那一刻之前拿到的播放地址这次改写不了。没测过的客户端版本，控制台会提示一句。

面板显示最近在用的播放器或直播窗口。面板和统计页的地址都在控制台里（「界面：」后面），浏览器没自动打开时，按 `p` 或者复制这个地址。

几个可以加在 `start.cmd` 后面的参数：

| 参数 | 作用 |
|---|---|
| `--client <路径>` | 指定 `哔哩哔哩.exe` 的位置 |
| `--no-client` | 不启动客户端，只打开统计页看以往的记录 |
| `--no-browser` | 启动时不自动打开面板 |
| `--lang zh-CN` / `--lang en` | 控制台和界面的默认语言（默认跟系统） |
| `--data <目录>` | 换一个数据目录 |

### 和扩展不一样的地方

- **记录分开**：桌面版的记录和设置在 `%APPDATA%\bpro-desktop`，和浏览器里的扩展互不相通，统计页里只有客户端里的播放。
- **只接入播放器窗口和直播窗口**：客户端的首页、动态等窗口不管，这些窗口里的预览播放不记。
- **刷新换节点**：重新加载客户端的播放器窗口，播放器从原来的位置接着放同一个视频，页面重新取播放地址时按当时的卡顿记录和测速选线。直播窗口还在加载时别点：客户端会转到它自己的「加载失败」页，点上面的「重新加载」就好。
- **没有的功能**：「B 站页面主题」（客户端有自己的主题，面板里收起来了）和快捷键 Alt+Shift+K。标记用播放器上的小旗子或面板。
- **关闭 B 站 P2P（测试功能）**：在客户端里同样生效。播放器只在窗口加载时读这个设置，打开或关掉后要让窗口重新加载：最省事的是在控制台按 `q` 退出、再双击 `start.cmd`；面板上正好出现「刷新换节点」时点它也行。和扩展一样，还没在中国大陆网络上实测。

### 更新和卸载

更新：在控制台按 `q` 退出，下载新版 zip，解压到原来的文件夹（覆盖）或新的文件夹都行。记录和设置在数据目录里，不受影响。

卸载：退出后删掉解压出来的文件夹。要连记录一起删，再删 `%APPDATA%\bpro-desktop`。

### 隐私和风险

- 调试端口只绑在本机（127.0.0.1），每次随机，退出时跟客户端一起关。开着的时候，本机的其他程序理论上也能通过它操作已登录的客户端，所以只在自己的电脑上用，不用时退出。
- 桌面版不改客户端的文件，不读 cookie、登录信息和客户端自己的数据目录。面板和统计页由只绑本机的网页服务提供，地址带每次启动随机生成的令牌，别的网站访问不了。
- 记录只存在本机，导出和脱敏规则同扩展。
- 这是非官方工具，可能被 B 站视为第三方用法；客户端更新后可能失效（比如关掉了调试端口）。杀毒软件可能对「启动别的程序并打开调试端口」报警。

### 桌面版的常见问题

| 问题 | 处理方法 |
|---|---|
| 提示「B 站客户端已经开着」 | 右键托盘图标「退出」，完全退出后桌面版会接着启动它 |
| 提示「找不到 B 站客户端」 | 用 `--client` 指定 `哔哩哔哩.exe` 的位置 |
| 提示「客户端没有打开调试端口」 | 客户端更新后可能关掉了这个功能，到 Issues 反馈客户端版本 |
| 提示「桌面版已经开着了」 | 同一个数据目录只能开一个，找到已经开着的控制台窗口 |
| 浏览器里没有打开面板 | 在控制台按 `p`，或复制「界面：」后面的地址 |
| 统计页里没有浏览器里的记录 | 桌面版和扩展分开记，见上面「记录分开」 |
| 点「刷新换节点」后直播窗口显示加载失败 | 点页面上的「重新加载」；以后等直播窗口加载完再刷新 |
| 窗口里报错后停住了 | 按任意键关闭；看报错里写的原因，确认 zip 完整解压了（`node` 文件夹里有 `node.exe`） |

反馈桌面版的问题时，写上 zip 文件名里的桌面版版本和控制台里显示的客户端版本。

## 隐私与权限

记录保存在本机浏览器的扩展存储中，扩展不上传记录，也未接入统计分析服务。它会不带 cookie 地请求 B 站网络位置接口，用于区分网络，保存国家、地区、城市与 ISP；不保存该接口返回的用户公网 IP。媒体请求中的 CDN / PCDN 节点 IP 属于诊断记录。为了算出扩展看到了多少流量，扩展在 B 站页面里读 B 站播放器按来源统计的字节数，并统计 WebRTC 数据通道收、发的字节数，只记字节数，不读传输的内容。选了浅色、深色或跟随系统时，扩展会把 B 站记主题的 cookie（`theme_style`）改成一样的，并在各个 B 站子域名的 localStorage 里记一个提示（`bilicdn:theme`）；选回「不改」后删掉提示，cookie 也不再改动。打开「关闭 B 站 P2P（测试功能）」时，扩展只改 B 站播放器在页面里读到的 P2P 开关，不改 B 站存着的配置，另在 B 站页面的 localStorage 里记一个提示（`bilicdn:p2p`），关掉开关后删掉。

| 权限 | 用途 |
|---|---|
| `storage`、`unlimitedStorage` | 在本机保存设置、记录、测速与网络档案 |
| `webRequest` | 观察媒体请求的节点、IP、耗时、速度与失败 |
| `alarms` | 调度周期测速 |
| `declarativeNetRequestWithHostAccess` | 只为扩展自己的测速请求设置 B 站的 Referer 和 Origin |
| `*.bilibili.com` | 注入播放观察、选线与标记功能，关闭 B 站 P2P 时改播放器读到的 P2P 开关，切换页面主题，并查询网络位置 |
| `*.bilivideo.com`、`*.bilivideo.cn`、`*.akamaized.net`、`*.szbdyd.com` | 观察媒体请求并测试 CDN / PCDN 节点 |

线路优化开没开，也会在 B 站页面的 localStorage 里记一个提示（`bilicdn:route`），下次打开页面时先读它；只记这个开关，不记播放记录。

没有播放活动的页面不写入播放记录；出现播放地址、媒体请求或其他播放活动的页面才会记录。要暂停记录、地址改写和测速，关闭面板右上角「启用」（B 站页面主题照常）。

## 常见问题

| 问题 | 处理方法 |
|---|---|
| 找不到 `manifest.json` | 先解压扩展 zip，选择直接包含该文件的目录 |
| 面板没有数据或播放器没有小旗子 | 切到 B 站播放标签页，确认扩展和「启用」已打开、「播放器标记按钮」已打开，再刷新页面 |
| 更新后按钮失效 | 在扩展管理页重新加载扩展，再刷新 B 站页面 |
| 改了节点但没有变化 | 开启线路优化并刷新；自动模式没有足够证据时会保留原节点，主地址不变也可能只调整备用顺序 |
| 测速结果为空或一直等待 | 开启自动测速并开始播放，等待缓冲；查看地址是否过期、是否因失败或排名而暂缓 |
| 关闭测速后仍有测速请求 | 线路优化可单独触发复测；若要停止全部测速，同时关闭线路优化或总开关 |
| HLS 仍然卡顿 | 尝试「FLV优先」并刷新直播间，对比缓冲和卡顿；可用格式由直播间提供 |
| 提示「扩展只看到约几成流量」 | 这个网络里 B 站的大部分音视频数据走 P2P 或扩展看不到的 PCDN，统计和线路优化只管得到扩展看到的部分；见「扩展看不到的流量」。默认只记下比例，不改 B 站的 P2P；想让流量都走 HTTP，可以试试「关闭 B 站 P2P（测试功能）」 |
| 打开「关闭 B 站 P2P」后没有变化 | 刷新 B 站页面（播放器只在加载时读这个设置），确认「启用」开着；B 站改了播放器的内部配置时这个功能会失效 |
| 关了 B 站 P2P 后播放变慢 | 这个网络上 P2P 可能更快：关掉开关、刷新页面恢复 |
| 得分高仍然卡 | 测速取没缓存的数据，和播放对不上；自动选线会参考页面实际请求的表现，页面上比原节点差的不再按测速换过去。标记真实问题，复查近期问题与时间轴 |
| 缓冲充足但画面卡 | 查看掉帧，尝试降低画质或检查解码；换节点未必改善 |
| 优化后变差 | 关闭线路优化并刷新；要回到默认观察状态，同时关闭自动测速 |
| 「安装以来」看不到早期记录 | 该范围只包含仍保留的数据，不会恢复过期或手动删除的记录 |
| 选了深色，有的页面没变 | 扩展用的是 B 站自己的深色主题，B 站没做深色的页面不会变；已打开的页面一般马上换，没换的刷新一下 |

仍需反馈时，在 [Issues](https://github.com/AbyssRain75/Bilibili-Playback-Route-Optimizer/issues) 写明扩展版本、浏览器版本、点播或直播、设置与复现步骤。需要附记录时，使用包含问题时段的普通导出并先检查内容。
