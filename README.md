# Bilibili Playback Route Optimizer

简体中文 | [English](README.en.md)

一个 Chrome / Edge 扩展，用来看 B 站视频和直播实际走的是哪个 CDN 节点、记下卡顿，也可以试着换一条更快的线路。

装好后默认是**观察模式**：只记录，线路还是 B 站自己选。想让扩展帮忙选节点，就打开**线路优化**；再打开**自动测速**，它会趁缓冲够的时候测一测各个节点的速度。这两个开关默认都是关的。

这是个人项目，和哔哩哔哩官方没有关系。换线路能不能变快，要看所在的网络、看的内容和当时有哪些节点可用，不是所有卡顿都能靠换线路解决。

更详细的操作、各项设置的默认值、选线和测速的规则，写在[使用说明](docs/usage.md)里（[English](docs/usage.en.md)）。

用 Windows 版 B 站 PC 客户端看的，可以试试[桌面版](#桌面版预览)（预览版）。

## 能做什么

- **看当前播放情况**：面板里能看到前方缓冲、掉帧、卡了几次，以及音视频实际是从哪个节点下的。
- **换线路**：点播可以让扩展自动选节点，也可以自己指定；直播可以自动选，或者优先用 B 站给的 FLV、HLS 线路。原来的地址都留作备用。
- **趁缓冲够的时候测速**：开了自动测速后，B 站页面在播放时每 30 秒试着测一轮，缓冲不够就先不测。结果按网络分开存。
- **记录卡顿**：缓冲卡顿、起播慢、播不出来会自动记下；也可以用播放器上的按钮、扩展面板或快捷键手动标记。
- **按网络看节点分布**：不同地方分到的节点不一样，同一个节点在不同地方快慢也不一样。统计页按网络汇总 B 站分到了哪些节点、连到哪些服务器、表现怎样，并给出几条结论；点「探查」可以把正在播放的视频或直播间的候选节点都测一遍。
- **看扩展看到了多少流量**：在中国大陆，B 站网页播放器的大部分音视频常常走 B 站自己的 P2P（浏览器之间的 WebRTC 连接），还有一部分走不在扩展网站权限里的 PCDN，这些扩展都看不到。统计页按网络显示扩展看到了几成、P2P 占多少、P2P 上传了多少；看到的不到一半时会提醒，统计和线路优化只管得到这一部分。默认只记字节数，不动 B 站的 P2P。
- **关闭 B 站 P2P（测试功能）**：默认关着。打开后 B 站网页播放器不再走 P2P，点播和直播都改走 HTTP，不再占上传。主要影响中国大陆网络，刷新页面后生效。在 P2P 效果好的网络上，关掉可能反而更慢；它依赖 B 站播放器的内部配置，B 站一改就会失效。目前还没在中国大陆网络上实测过。
- **回看和导出记录**：统计页汇总节点表现、问题标注、播放会话和网络变化，可以导出 JSON，拿去分析或者反馈问题。
- **中英文界面**：默认跟浏览器的界面语言走，面板和统计页上也能手动切换。
- **B 站页面浅色 / 深色**：用的是 B 站自己的深色主题，不登录也能用，也可以跟随系统。默认不改。

PCDN（也叫 MCDN）是 B 站租用的家庭宽带这类节点，走的是普通的 HTTP 请求，和上面说的浏览器之间的 P2P 不是一回事。换个网络，PCDN 的表现可能差很多。自动选线会避开认得出的 PCDN 和最近卡过的节点；找不到合适的节点时，也会留在原线路上。

## 安装

需要 **Chrome 或 Edge 120 以上**。扩展还没上架商店，现在要从本地文件夹加载。暂时不支持 Firefox。

### 1. 下载并解压

到[最新版本的发布页](https://github.com/AbyssRain75/Bilibili-Playback-Route-Optimizer/releases/latest)，在 **Assets** 里下载：

```text
Bilibili-Playback-Route-Optimizer-<版本>-chromium.zip
```

解压到一个以后不会挪动的文件夹。要下的是这个扩展包，不是 GitHub 自动附带的 **Source code (zip)** 或 **Source code (tar.gz)**，那两个是整个仓库的源码。扩展包解压后，根目录里直接就有 `manifest.json`。

### 2. 在浏览器里加载

| 浏览器 | 在地址栏打开 | 操作 |
|---|---|---|
| Chrome | `chrome://extensions` | 打开「开发者模式」，点击「加载已解压的扩展程序」 |
| Edge | `edge://extensions` | 打开「开发人员模式」，点击「加载解压缩的扩展」 |

把表里的地址粘到地址栏打开。选文件夹时，要选**直接包含 `manifest.json` 的那一层**；有的解压软件会多套一层目录，这时再往里点一层。

扩展列表里出现 **Bilibili Playback Route Optimizer** 后，确认它是启用的。再点工具栏上的拼图图标，Chrome 里把它固定，Edge 里选「在工具栏中显示」，以后点一下就能打开。

### 3. 确认装好了

1. 把之前开着的 B 站页面刷新一下，播放一个视频或者进一个直播间。
2. 点工具栏上的扩展图标，打开面板。
3. 右上角的**启用**应该是开着的，模式显示**观察模式**；「当前播放」里是正在看的页面，数据会慢慢出来。

到这一步扩展已经在记录了。想让它帮忙选线路，接着看下面的设置。

用 Git 的话，也可以直接克隆这个仓库，加载里面的 `chromium/` 文件夹，不用装 Node.js，也不用构建。加载未打包扩展的步骤也可以看 [Chrome 的官方说明](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-unpacked)和 [Edge 的官方说明](https://learn.microsoft.com/en-us/microsoft-edge/extensions/getting-started/extension-sideloading)。

## 操作指南

### 打开线路优化

1. 打开一个 B 站视频或直播间，点扩展图标。
2. 在**线路设置**里打开**线路优化**。想让它边看边攒测速结果，再打开**自动测速**。
3. 第一次用的话，**点播节点**和**直播线路**都选**自动**就行。
4. 刷新 B 站页面。播放器重新拿播放地址的时候，才会按新设置走。

两个开关互不依赖：只开自动测速，只是攒测速结果，播放还走 B 站原来的线路；只开线路优化，也会参考最近的卡顿和已有的测速结果，选线时可能顺手再测一次。

点播的「自动」会避开最近 30 分钟里卡得够多的节点，记一次「少量卡顿」不一定就换。B 站分配的官方节点最近没出问题时，别的节点测速得分要高出 20% 以上才换，免得为一点点差别来回切。刚装好、既没有测速结果也没卡过的时候，一直用原节点是正常的。

如果 B 站分配的节点在页面上表现就很好（实际请求首字节很快、几乎不失败），测速分数再高也不换，因为测速取的是一小段没缓存的数据，跟播放时取的热门内容不是一回事。按测速换过去的节点也得测过几次才算数，「探查」测的那一次不算；页面上已经用过、表现好的节点不用等。

想试试某个点播节点，就在**点播节点**里选它，然后刷新页面；不好用再改回**自动**。直播用「自动」还是卡，可以分别试试 **FLV优先**和 **HLS优先**。直播只能在 B 站给这个房间提供的线路和格式里选。

### 看懂当前播放状态

先切到正在播放的 B 站标签页，再打开面板。**当前播放**里有前方缓冲、近期掉帧、会话卡顿和正在用的节点；展开**高级**能看到**近期问题**、**测速结果**和**节点明细**。

这几个数要结合着看：

| 看到的情况 | 大概是什么原因、怎么办 |
|---|---|
| 缓冲很少，播放器反复转圈 | 网络或者当前节点跟不上。先标记一下；开着线路优化的话，可以刷新换一条线路试试 |
| 缓冲充足，但掉帧明显 | 多半是解码或渲染跟不上，可以降低画质，或者看看硬件解码有没有开 |
| 缓冲充足，掉帧也少 | 数据是够的，不一定要换节点 |

能读到播放器状态时，测速要等缓冲够了才测：点播是前方缓冲至少 15 秒（快播完时缓冲到结尾也行），或者正暂停着；直播是没在转圈、缓冲至少 1 秒。读不到播放器状态时，定时测速也可能照常跑，所以不能保证一点都不影响播放。

每轮最多测 4 个节点，每个最多读 512 KB 左右，一轮合计 2 MB 左右，测 HLS 时还要另外取播放列表；表现差的节点会少测。「探查」测的节点更多，流量另算。刚装好时没有测速结果、缓冲不够时测速停着，都是正常的。

### 播放不顺时做个标记

看的时候用哪种方式都行：

- **播放器按钮**：点控制栏右边的小旗子，记一次「较多卡顿」。鼠标放上去能看播放状态，也能选别的问题类型。
- **扩展面板**：在**手动问题标注**里点「少量卡顿」「较多卡顿」「无法播放」或「音画不同步」。要写备注的话，先写备注再点按钮。
- **快捷键**：按 **Alt+Shift+K**，不用打开面板就能记一次「较多卡顿」。

点错了可以在面板里点**撤销**，撤回这个页面最近的一次标记。用不着小旗子的话，关掉**播放器标记按钮**就行。快捷键可以在 `chrome://extensions/shortcuts` 或 `edge://extensions/shortcuts` 里改；按了没反应，先看看是不是和别的快捷键冲突了。

标记时会一起记下当时的缓冲和掉帧。判断为解码或渲染问题的标记，还有音画不同步的标记，不会算到节点头上。面板上出现**刷新换节点**按钮时，可以挑个方便打断播放的时候点它，重新选一次线路；能不能换到别的节点，要看当时有哪些可选。

### 查看统计、导出记录

点面板右上角的**统计**，选**本日**、**本周**或**安装以来**，下面有**节点分布**、**节点表现**、**问题标注**、**会话时间轴**和**网络与页面**。

**节点分布**按网络分开汇总，默认显示当前网络。让视频或直播保持播放，到统计页点**探查这个网络**，会把它的候选节点各测一次。点播大约 10 MB；缓冲不够会先等，一共等了 2 分钟还不够就停下。自动测速关着也能用，但「启用」要开着。同时开着好几个播放页的话，测的是最近在下数据的那个。测完统计会自动刷新。

顶部**媒体请求**下面写着扩展看到了多少媒体流量，包括 P2P 占多少、上传了多少，PCDN 加载器取过数据的话也会写上；节点分布里每个网络也有这么一条。旧版本留下的记录没有这一项，算作「不知道」。

统计只包括还没过期的记录，「安装以来」也找不回已经删掉的数据。记录默认留 **15 天**，可以在统计页右上角的**记录保留**里改成 7 天到 6 个月。改短会删掉一部分记录时，页面会先确认一次。

要反馈问题，就选一个包含出问题那段时间的范围，点**导出 JSON**，选**普通导出（脱敏）**。这份文件里有分析要用的数据，但还是会带着节点域名和 IP，以及出过问题的视频、直播间地址和备注，发出去之前先看一眼。**完整信息导出**是所选范围的原始记录（连同必要的前后记录），包括浏览和网络细节，自己留着用就好。

### 切换 B 站页面的浅色 / 深色

在面板的 **B 站页面主题**里选**浅色**、**深色**或**跟随系统**，开着的 B 站页面马上就换，不用刷新。默认是**不改**，按 B 站自己的设置来。用的是 B 站自己的深色主题（登录后在头像菜单 → 主题里也能换，两边会同步），B 站没做深色的页面不会变。这个选项只管页面颜色，扩展暂停时照样有效。

### 关闭 B 站 P2P（测试功能）

在中国大陆网络上测试时，B 站网页播放器的大部分音视频数据走的是 B 站自己的 P2P，也就是在你的浏览器和其他观众之间互相传：会占上传带宽（直播几分钟就可能传出去几十 MB），还会把看过的视频存在浏览器里给别人取，而且这部分扩展看不到。B 站网页上没有关掉它的选项。

在面板里打开**关闭 B 站 P2P（测试功能）**，再**刷新 B 站页面**，播放器就不用 P2P 了，点播和直播都改走 HTTP。这个开关默认是关的，不动 B 站原来的行为。几点说明：

- 这是测试功能，**扩展里的这个开关还没在中国大陆网络上实测过**。之前只在大陆的数据中心网络上手动关过 P2P，测了两个低码率视频和两个直播间，都能正常播放，也没有变慢；家庭宽带上效果怎样还不知道。
- 主要影响中国大陆网络。播放器本来就不用 P2P 的话（海外网络大多如此），开不开差别不大。
- 在 P2P 效果好的网络上，关掉后可能反而变慢。觉得慢了，关掉开关、刷新页面就恢复了。
- 它依赖 B 站播放器的内部配置，B 站一改就会失效，失效时就跟没开一样。
- 关掉 P2P 以后，不在扩展网站权限里的 PCDN 扩展照样看不到。
- 扩展暂停时不起作用。关掉这个开关或者暂停扩展后，也要刷新页面才会恢复用 P2P。浏览器里已经存下的 P2P 缓存不会清掉。

刷新后播一会儿，再到统计页看流量来源和关了 P2P 的会话数。统计总览会把所选时间范围里以前用过 P2P 的记录也算进去，所以 P2P 占比不一定马上降到 0。

### 暂停扩展、切换语言

关掉面板右上角的**启用**，扩展就暂停：不记录、不再改播放地址、不测速，设置和已有记录都还在，B 站页面主题照常有效。已经在播的不会自己切回原线路，想按 B 站原来的设置播，暂停后刷新一下页面。重新打开后也要刷新，当前的播放才能完整记下来。

只是想回到 B 站自己选线，关掉**线路优化**再刷新页面就行；不想再定时测速，就把**自动测速**也关掉。

面板和统计页右上角的 **EN / 中文** 按钮用来切换界面语言，播放器上的按钮也跟着换。

## 更新与数据保留

1. 更新前可以先在统计页导出一份记录留着。导出的 JSON 是给分析用的，目前不能导回去恢复记录。
2. 下载新版扩展包并解压，确认解压完整、里面有 `manifest.json`。
3. 把**原来加载的那个扩展文件夹**清空，新版文件复制进去，文件夹本身和位置都别变。用 Git 装的，在发布仓里 `git pull` 就行。
4. 打开浏览器的扩展管理页，点扩展卡片上的**重新加载**。
5. 刷新开着的 B 站页面。

记录和设置存在浏览器的扩展存储里，这样替换文件、重新加载都不会丢。**不要点「移除」，也不要挪文件夹**：移除会把扩展数据一起删掉；从别的路径加载未打包扩展，浏览器可能会把它当成另一个扩展。

## 常见问题

| 问题 | 怎么办 |
|---|---|
| 加载时提示找不到 `manifest.json` | 先解压 zip，再选直接包含这个文件的那层目录 |
| 工具栏上找不到扩展图标 | 点浏览器的扩展菜单（拼图图标），确认扩展是启用的，再固定图标或选「在工具栏中显示」 |
| 面板里没有播放数据 | 切到 B 站视频或直播间的标签页，确认「启用」开着，刷新页面再开始播放 |
| 改了设置，节点没变 | 刷新页面。选线发生在重新拿播放地址的时候；「自动」觉得没必要换时，也会保留原节点 |
| 测速结果一直是空的 | 确认「自动测速」开着，开始播放，等缓冲够了再给它一轮测速的时间 |
| 统计里的流量比实际看的少，提示「扩展只看到约几成流量」 | 在中国大陆，B 站网页播放器的大部分音视频常常走 B 站自己的 P2P，或者走不在扩展网站权限里的 PCDN，这部分扩展看不到，统计、卡顿归因和线路优化都只管得到看到的那部分。默认只记下比例，不动 B 站的 P2P；可以试试**关闭 B 站 P2P（测试功能）**，但它管不到 PCDN，也不保证能看到全部流量 |
| 打开「关闭 B 站 P2P」后没变化 | 刷新 B 站页面，播放器只在加载时读这个设置；再确认「启用」开着。B 站改了播放器的内部配置时，这个功能会失效 |
| 测速分数很高，播放还是卡 | 测速取的是没缓存的数据，分数高不等于播放快。「自动」会参考页面实际请求的表现：换过去的节点在页面上比原节点差，以后就不会再按测速换过去。卡的时候标记一下，「自动」会避开它 |
| 开了优化反而更卡 | 关掉「线路优化」再刷新页面；想和纯观察模式对比，把「自动测速」也关掉 |
| 更新后按钮没反应 | 重新加载扩展，再刷新 B 站页面，让页面上的脚本和新版扩展对上 |

还有问题的话，到 [Issues](https://github.com/AbyssRain75/Bilibili-Playback-Route-Optimizer/issues) 反馈，写上浏览器和扩展版本、是点播还是直播、线路设置，以及怎么复现。最好附一份包含出问题时间段的普通导出文件，查起来会快很多。

## 隐私

- 记录只存在本机浏览器的扩展存储里，扩展不上传记录，也没有接入任何统计分析服务。
- 为了区分不同网络下的测速结果，扩展会查询 B 站的网络位置接口（`api.bilibili.com/x/web-interface/zone`，不带 cookie），保存 B 站返回的国家、地区、城市和 ISP，不保存你的公网 IP。媒体请求里的 CDN 节点 IP 会作为诊断数据记下来。
- 开了自动测速或线路优化，或者手动点了「探查」，扩展可能会向 B 站的 CDN 节点发测速请求，产生上面说的额外流量。
- 只记录有播放的页面；个人空间、动态这类没有播放的页面不记。
- 为了算出扩展看到了多少流量，扩展会在 B 站页面里读 B 站播放器自己按来源统计的字节数，并统计页面里 WebRTC 数据通道收发的字节数（B 站的 P2P 用的就是它）。只记字节数，不读传输的内容，记录同样只存在本机。
- 选了浅色、深色或跟随系统时，扩展会把 B 站自己记主题的 cookie（`theme_style`）改成同样的值，登录后 B 站按它显示主题；同时在各个 B 站子域名的 localStorage 里记一个提示（`bilicdn:theme`，记着选的是哪种），页面一打开就先按它换颜色，免得先闪一下浅色。选回「不改」后，开着的页面马上删掉这个提示，其他子域名的等下次打开页面时删；cookie 也不再改动。
- 线路优化开没开，也会在 B 站页面的 localStorage 里记一个提示（`bilicdn:route`），下次打开页面时先读它。只记这个开关，不记播放记录。
- 打开「关闭 B 站 P2P」时，扩展只改 B 站播放器在页面里读到的 P2P 开关，不改 B 站存着的配置；另外在 B 站页面的 localStorage 里记一个提示（`bilicdn:p2p`），关掉开关后删掉。
- 过期记录会自动清理。普通导出只对一部分信息脱敏，仍然带着出问题会话的地址、标记备注和节点 IP，分享前先检查；完整导出不要公开分享。

## 权限说明

| 权限 | 用途 |
|---|---|
| `storage`、`unlimitedStorage` | 在本机保存设置、记录和测速结果；记录多了也不受扩展存储默认容量的限制 |
| `webRequest` | 观察媒体请求的节点、IP、耗时、速率和失败情况，只看，不拦也不改 |
| `alarms` | 每 30 秒安排一轮自动测速 |
| `declarativeNetRequestWithHostAccess` | 只给扩展自己发的测速请求设置 CDN 要求的 B 站 Referer 和 Origin，不影响页面的请求 |
| `*.bilibili.com` | 读取播放信息、开了线路优化时改写播放地址、开了「关闭 B 站 P2P」时改播放器读到的 P2P 开关、识别卡顿、显示播放器按钮、切换页面主题、查询网络位置 |
| `*.bilivideo.com`、`*.bilivideo.cn`、`*.akamaized.net`、`*.szbdyd.com` | 观察媒体请求，测试 B 站 CDN 和 PCDN 节点 |

## 桌面版（预览）

桌面版把扩展的观察、选线、测速和标记用在 **Windows 版 B 站 PC 客户端**里：它启动客户端并接入，在客户端的播放器窗口和直播窗口里放进扩展的页面脚本，扩展的后台原样在桌面版里跑，所以记录、选线和测速的规则和扩展一样。面板和统计页在默认浏览器里打开。现在是预览版（0.x），在客户端 1.19.0 和它自动下载的更新 1.20.0 上测过。

### 安装和启动

1. 在 [Releases](https://github.com/AbyssRain75/Bilibili-Playback-Route-Optimizer/releases) 里找标着 **Pre-release** 的桌面版（标签以 `desktop-v` 开头），下载 `Bilibili-Playback-Route-Optimizer-Desktop-<版本>-win-x64.zip`。
2. 解压到一个文件夹。zip 里带着 Node.js 的官方运行程序（`node\node.exe`），不用另装。
3. 先从托盘**完全退出** B 站客户端（右键托盘图标 →「退出」），再双击文件夹里的 `start.cmd`。

会出现一个控制台窗口：桌面版启动客户端、接入后，在浏览器里打开面板。控制台里按 `p` 打开面板，`s` 打开统计页，`q` 退出；关掉控制台窗口时，客户端也跟着正常退出。和扩展一样，默认是观察模式，线路优化和自动测速都关着。

### 和扩展不一样的地方

- 只支持 Windows（64 位），只接入播放器窗口和直播窗口，客户端的首页等别的窗口不管。
- 客户端要由桌面版启动。已经开着的客户端要先从托盘退出，桌面版会等它退出后再启动。
- 记录和设置与浏览器里的扩展分开，存在 `%APPDATA%\bpro-desktop`。
- 没有「B 站页面主题」，也没有快捷键 Alt+Shift+K；标记用播放器上的小旗子或面板。
- 「刷新换节点」重新加载客户端的播放器窗口，从原来的位置接着放。

### 隐私和风险

- 桌面版带调试端口启动客户端。端口只绑在本机（127.0.0.1）、每次随机，退出时跟客户端一起关；开着的时候，本机的其他程序理论上也能通过它操作已登录的客户端。
- 桌面版不改客户端的文件，不读 cookie 和登录信息。面板和统计页由一个只绑本机的网页服务提供，地址里带每次启动随机生成的令牌。记录只存在本机。
- 这是非官方工具，可能被 B 站视为第三方用法；客户端更新后也可能失效（比如关掉了调试端口）。杀毒软件可能会对「启动别的程序并打开调试端口」报警。

更多操作、更新方法和常见问题见使用说明的[桌面版](docs/usage.md#桌面版预览)一节。

## 参考

这些项目在设计上给了不少启发，但没有用到它们的代码：

- [stabruriss/bilibili-accelerator](https://github.com/stabruriss/bilibili-accelerator)：缓冲够了再测速、识别 PCDN 并降低它的优先级、遵守 Akamai 的签名限制。

- [enhanced-h264ify](https://github.com/alextrv/enhanced-h264ify)：硬件解码支持方面的资料。
